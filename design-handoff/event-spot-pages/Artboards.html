Event & spot pages

Four public pages, no photography anywhere. Desktop is 1180px of content with 18px side padding; the mobile frames are the same documents at 390px. Every frame below is the live page — the prototype bar at the top of each is a switcher for these states, not part of the page. All four link to each other with real hrefs.

1 · Event page

The events-list modal promoted to a page: same header band, same fact grid, same address / phone / listing rows. What the page adds is a status band that survives being screenshotted out of context, a real H1 naming event and town, a private “I’m going” note, and three onward routes. Missing fields get a dashed “not listed” chip rather than an empty row.

Why “over” reads first

Three signals fire before any reading happens: the band drops from pink to ink, a red stamp sits where the blurb starts, and the status line states the date plus “12 weeks ago”. Nothing else on the page is red or black-banded, so the state is legible in a thumbnail.

The page still earns the visit: in state C the three onward blocks (near this town / at this venue / spots nearby) move above the blurb, so the first thing under the stamp is somewhere else to go.

The private note becomes a “Went” record with a link to log tricks. Still private — no attendee list exists anywhere.

Not built, deliberately: no attendee list, no ticketing, no comments.

2 · Spot page

About 25 words of unique data, so the structure carries it. Tags become a real “what’s here” section — one cell per feature, each explaining the feature and linking to the tricks it suits — and the map gets the weight a photo would have had. Submitters are never shown.

Thin listing, honest page

The sparse spot doesn’t pretend to be full: two feature cells, a line saying two features is all it has, and the map grows to fill the room the missing cells left.

“No address listed” is followed by the reason it doesn’t matter — the pin is exact, so directions still work. Phone reads “no phone — street spot”.

Reporting sits bottom-right on both variants, low-key and underlined, next to a line about why spots go stale.

Event pins are a dashed circle labelled town-accurate; spot pins are a solid diamond labelled exact. Same map component, different claim.

3 · Events list

The shipped row is kept as it is — colour-coded date block, sport chips with icons, price, Details and I’m going. Two things change: the event name is now a real link to the event page, and the Details modal gains a View full page CTA. Past events get their own view with a year and town index.

Decision: keep both, one CTA between them

The modal is the quick look and it keeps I’m going, so the common case never leaves the list. What it gains is a yellow View full page CTA beside it, plus one line naming what the page adds: the map, what else is on nearby, other events at this venue, and a link you can share.

The event name in the row is a link, and so is the title inside the modal — that gives the row a hover URL, a middle-click and a crawl path, which a button-only row cannot have.

On past rows I’m going is replaced by Full page →: going is meaningless once it is over, and the onward links are the only reason to open it.

Changed from the earlier pass, which retired the modal. The row itself is the shipped design, untouched.

4 · Spots list

The card click has to mean two things at once. It doesn’t: the card is a link, the map is a button.

Card is a link, map is a button
Decision: navigation owns the card

The whole card body is a stretched link to the spot page — the frequent, expected gesture, and the one that needs a real URL. Selecting a spot on the map is an explicit Show on map button in the card footer, sitting above the link.

The map stays useful: choosing a card marks it with a yellow keyline, the pin swells to solid orange, and the panel names the chosen spot with its own link out. Pins are clickable in the other direction.

On a phone the sheet is docked above the bottom nav with its handle always visible. Tapping Show on map raises it; the sheet leads with a full-width Open spot page bar, so the thumb never has to hunt for the link behind the map.

Rejected: whole card selects the map, with a small “page” link. It buries the crawlable route in a 12px target and leaves the card with no href.
